# 网络表单填报

先读公共 **`browser-guide`**。优先使用 **`xiaobei_browser`** 工具，普通表单站点复用持久化 `session="default"`，以 `headed=true` 打开可见窗口，供用户观察与介入。登录、验证码和人工等待按 browser-guide 执行；不使用原生 browser、Chrome/CDP 或随机会话。

## 1. 收集完整字段

先完整浏览表单的各个页面、步骤和栏位，只查看和记录，不急着填写。记录字段 label、类型、是否必填、字数与格式限制、选项、附件要求，以及级联下拉、日期、富文本等特殊控件。

将清单持续写入工作区 `form-fields-<项目简称>.md`，按表单页面组织。例如：

```markdown
# 项目申报字段清单

## 企业基本信息
- 企业名称 [必填] [text] [限50字]：
- 所属行业 [必填] [级联下拉]：

## 项目情况
- 产品与技术 [必填] [富文本] [限2000字]：
- 融资金额 [number] [单位万元]：

## 附件
- 营业执照 [必填] [PDF/图片]：
```

## 2. 准备内容与附件

依据用户已提供的资料和获准读取的工作区材料补全清单。缺失的事实、选项或附件向用户确认，不编造；富文本先准备正文，再写入页面。确认币种、单位、日期格式和各字段限制。

## 3. 填写和验证

页面就绪后取得本任务的 lease，后续调用携带 token。用户需要接管或处理验证时设置 `lease wait`；恢复后 renew，收尾时 release。

- **文本和富文本**：先 snapshot 找到真实输入区域的 ref，点击聚焦。需要逐键输入的受控组件、mask 或富文本编辑器，先用当前聚焦元素的全选/Backspace 清空，再用 `act kind="type", replace=false` 通过键盘事件追加正文。普通字段也可使用默认替换式 type；输入方式不能代替结果核验。
- **输入后核验**：让框架完成渲染，snapshot 检查可见值、placeholder 和报错；必要且获允许时 evaluate 读取当前值。富文本须核对编辑区而非工具栏。失败时重新聚焦，清空后重试一次；仍失败则记录为待人工填写。
- **下拉与级联**：点击展开，自新 snapshot 找到选项并点击；原生单选 select 可按可见 label 选择，或使用聚焦后的方向键/Enter。自定义多选逐项核对，不把其伪装成原生单选 select。
- **Radio / Checkbox**：点击对应选项，snapshot 核对选中状态；需要时聚焦后按 Space。不要盲目重复切换。
- **日期**：从日期面板选择，或按页面支持的格式键入后核验。不要以直接修改 DOM 的方式伪造成功。
- **文件上传**：用 upload 的 `paths` 和真实文件 input 的 `inputRef`/selector，遵守上传目录、入站媒体和 workspace 文件策略。多文件一次传入数组，并检查页面回显文件名和上传状态；用户未提供的附件记为缺项。

禁止通过 evaluate 直接赋值 `innerHTML`、`textContent` 或 `value` 来绕过框架状态。不能因为 placeholder 消失就宣称数据已被表单保存，也不能保证某个输入方法能通过所有站点验证。

## 4. 切页前保存

每页填写后检查暂存、保存草稿或自动保存状态。有暂存按钮时保存，等待成功提示并核对关键字段；切到另一页再返回时，确认内容仍存在。

没有保存按钮和自动保存指示时，截图说明情况，请用户确认是否继续切页。`OUTCOME_UNKNOWN` 或保存超时先核对实际结果，不自动再次提交保存或发布动作。

## 5. 提交前确认与收尾

逐页复核所有字段、单位和附件，把截图或清单交用户审阅，明确列出未填写、无法验证或等待人工处理的项。告知用户：**内容已填写，请检查后手动提交，或明确指示我提交。**

最终提交须遵循用户本次授权；没有明确提交指令时保留草稿。获准提交后检查成功回执、编号或页面状态，结果未知时先核查，不重复提交。

释放本任务 lease，按 browser-guide 清理自己的标签和已结束的会话；等待用户登录或审阅的窗口不关闭。
