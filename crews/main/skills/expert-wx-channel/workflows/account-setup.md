# 视频号起号、定位梳理与老号接手 Workflow

新号起号、账号定位梳理、内容支柱搭建、冷启动方案、默认 `dna-0` 初始化、老号接手走这个 Workflow。独立账号对标走 `account-benchmark.md`。

## 入口判断

用户说以下话时走：

| 意图 | 典型说法 | 处理 |
| --- | --- | --- |
| 新号起号 | “我想做个视频号，从零开始” | 业务信息检查 -> 定位梳理 -> 冷启动方案 -> 初始 `dna-0` |
| 定位梳理 | “梳理一下内容方向”“搭建内容支柱” | 定位梳理 -> 必要时更新 `dna-0` |
| 老号接手 | “这个号以后你来接手”“账号还行，先按原风格做” | 老号样本采集 -> 建立或更新 `dna-0` |
| 老号诊断 | “帮我看看这个号还有没有救”“给我们号把个脉” | 老号样本采集 -> 判断延续或重建 |
| 默认 DNA 初始化 | “初始化默认 DNA” | 按新号 / 老号路径建立 `dna-0` |

## 从零开始打造新号

### 初始化原则

1. 默认 DNA 固定为 `dna-0`。
2. 除 `account-benchmark.md` 分流的对标样本外，用户不指定 DNA 时，参考视频样本和后续新增样本默认累积到 `dna-0`。
3. `dna-0` 可以由参考账号、参考视频、用户想法和 `business_knowledge.md` 共同形成，不绑定单一账号名。
4. 若 `wx_channel/dna/dna-0/dna-0.dna.md` 已存在，不覆盖重建；新资料按 `style-dna.md` 的更新流程进入。
5. 独立对标样本不直接写入 `dna-0`，必须走 `account-benchmark.md` 并进入独立 DNA；用户明确采纳的局部规则可通过局部 DNA 融合更新 `dna-0`。

### Step 1 - 业务信息检查

先读取 Workspace 根目录的 `business_knowledge.md`，检查三项关键信息：

| 关键信息 | 最低要求 |
| --- | --- |
| 产品 / 服务概括 | 能说明卖什么、解决什么问题、核心差异 |
| 收费项目 | 能说明主要收费方式、产品或价格区间 |
| 目标受众 | 能说明具体人群、痛点、使用场景 |

任一项为空、仅有占位符或互相矛盾时，先与用户补齐。不要凭空编造。

用户思路不清晰、多个定位方向难以取舍或商业假设冲突时，调用顶层 `council` 技能辅助梳理；`council` 不收纳进视频号专家包。

更新 `business_knowledge.md` 前必须征得用户同意，并遵守 Workspace 根 `AGENTS.md` 的治理规则。

### Step 2 - 定位梳理

新号起号、老号重建和用户要求“梳理定位 / 内容支柱”时都必须执行。已有清晰定位且用户只要求接手制作时，可以基于现有账号样本校验定位，不重新发起完整讨论。

#### 输入

1. `business_knowledge.md` 中的产品、服务、收费、受众和红线。
2. 用户目标：个人 IP / 企业品宣 / 电商带货 / 私域引流。
3. 已有账号样本和表现线索（如有）。
4. 用户提供的对标方向（如有）。

#### 输出（起号计划字段）

1. **定位句**：我帮助[目标人群]，用[独特优势/内容价值]解决[具体痛点]，让他们获得[理想结果]。
2. **三维坐标**：为谁拍 × 凭什么信你 × 用什么标签记住你。用「场景拆解法」锁定买单人群（核心场景、核心痛点、决策关键）；想讨好所有人 = 标签混乱 = 起号失败。
3. **人设三标签**：身份标签（老板/创始人/主理人/专家/源头供应链/品牌）+ 特质标签（直爽、专业、抠细节、敢说真话…）+ 价值标签（源头价、避坑、实测、行业内幕…），各取 1 个组合成记忆点；遵循三度原则：专业度、可信度（展示真实场景、坦然提缺点）、亲近度（生活化语言替代广告话术）。
4. **内容矩阵**：人设/信任类 40% + 种草/价值类 40% + 转化/互动类 20%；带货号提高种草与转化比例，品宣/个人 IP 号提高人设与干货比例。每个支柱至少 5 个候选选题，按「易拍优先」排序。
5. **关键词地图**：类目词、痛点词、场景词、人群词、商业词。
6. **主页装修**：主页文案、置顶视频规划、合集规划。
7. **约束与风险**：合规边界（广告法绝对化用语、类目资质）、品牌语气、产能、出镜可行性。

人设记忆点检查：身份信号是否在前 3 秒可识别；是否有真实可公开的短板与成长线；人设是否与出镜者或品牌一致、不会硬凹翻车。品牌号要提炼“品牌人格”——说话语气、价值主张、固定视觉。

用户思路不清、多个方向冲突或商业假设不一致时，先用少量问题澄清；仍难判断时调用顶层 `council` 技能辅助决策。

### Step 3 - 冷启动方案

定位确认后给出可执行的冷启动与节奏方案：

1. **私域热启动**（发布后第一动作）：在 10 个左右核心社群/好友中引导真实的「点赞-评论-转发」三连，话术是请对方判断“这条对不对、有没有用”，不是统一刷互动。底线：不买量、不互刷、不群控、不强制点赞评论、不打扰无关人群。
2. **冷启动渠道选择**（按账号资源选 2-4 个）：朋友圈（转发必带文案）、微信社群（遵守群规，分享必带文案）、公众号互推（如有）、1 对 1 私聊（培养观看习惯 + 收集意见）、大号评论区短句神评（不硬广）、同城定位（有实体门店时）。
3. **九条视频实验**（新号 / 低播放号 / 定位待验证时）：9 条同一垂直定位，每条只改 1-2 个关键变量（钩子、场景、选题角度、人设表达），用设计表记录「选题角度 / 观看理由 / 3秒钩子 / 验证假设」；一周后按账号内部中位数找高表现视频，读评论标注原因，选一个最可能有效的变量做下一轮 3 条验证。
4. 起号期保持周更 3-5 条，前 5 条必须垂直打透一个定位。

经验阈值仅作提示（完播率 ≥ 30% 健康线、互动率 ≥ 5%、社交推荐占比 > 40% 等均为经验假设）；样本太小时先收集 10-20 条同类内容再做大调整。

### Step 4 - 新号初始 DNA 路径判断

先区分两种“参考”：

- 用户明确要把参考账号或视频作为默认 DNA 的初始来源 -> 走下方路径 A / B / C，产物进入 `dna-0`。
- 用户只是要分析参考账号、比较风格差异或寻找可借鉴模式 -> 走 `account-benchmark.md`，对标样本进入独立 DNA，不直接写入 `dna-0`。
- 意图不明确时，先向用户确认“是纳入默认 DNA，还是只做对标比较”。

#### 路径 A：用户提供了参考账号或参考视频样本

1. 按 `style-dna.md` 获取样本（文字稿优先；视频文件先转写；视频号链接无公开路径，请用户提供文字稿或视频文件）。
2. 目标 DNA 固定为 `dna-0`。
3. 每条生成 report。
4. 运行 `wx-channel-style-profiler build --dna-id dna-0`，生成 DNA 文档与 template。
5. 把定位、选题、简介包装、账号简介、内容形式与比例、发布习惯、高数据创意、社交分享、口播 DNA 与制作管线发送用户确认。
6. 用户调整意见按 `style-dna.md` 的“用户输入转译”更新到 `dna-0`。

用户没有明确权重时，所有 report 默认权重为 1。对标账号初始参考建议批量收集 10 条视频样本；用户明确提供单条或少量样本时仍可建立 `dna-0`，但必须标注覆盖不足，不得称为稳定结论。批量账号样本才填账号运营子模块（简介写法、发布习惯）。

#### 路径 B：用户暂无参考，但业务信息完整

Agent 基于 `business_knowledge.md` 提炼搜索关键词，建议用户到视频号站内搜索同类头部或表现较好的账号：

1. 优先找观众相近、承诺清晰、近期仍活跃的账号。
2. 优先选择分享和评论信号强的视频；播放量只作次要参考。
3. 用户找到账号或视频后，把文字稿 / 视频文件 / 截图数据提供给 Agent，回到路径 A。
4. 说明限制：Agent 没有视频号站内公开抓取路径，账号发现和文案获取必须经用户之手。

#### 路径 C：用户拒绝外部参考或已有明确想法

1. 结合 `business_knowledge.md`、用户定位、目标观众、变现方式和用户思路，提炼 `dna-0`。
2. Agent 直接按视频维度框架（`video-dna-framework.md`）编写：

```text
wx_channel/dna/dna-0/dna-0.dna.md
wx_channel/dna/dna-0/dna-0.template.md
```

3. DNA 文档必须标明来源是“业务信息 + 用户指定方向”，没有视频样本统计。
4. 能确定的规则写为执行要求；未确定维度写“待校准”，不得虚构单条证据。
5. Template 仍必须给出可执行的 Brief / 内容生产语义段；不能只有抽象定位词。
6. 将 DNA 摘要和待校准点发给用户确认，再按用户意见转译修订。

后续获得真实视频样本时，按 `style-dna.md` 生成 report 并更新 `dna-0`。

### Step 5 - 默认 DNA 落盘

完成路径 A / B / C 后，确认以下文件存在且互相一致：

```text
wx_channel/dna/dna-0/reports/
wx_channel/dna/dna-0/covers/
wx_channel/dna/dna-0/dna-0.dna.md
wx_channel/dna/dna-0/dna-0.template.md
```

检查要求：

- DNA 文档说明样本来源、覆盖数量、权重、例外和待校准点。
- Template 能由 DNA 文档推导，直接指导定位、选题、简介包装、内容形式、发布节奏、高数据创意、社交分享、互动与制作交接。
- 用户输入已转译为维度级规则，不是原话堆积。
- 对标样本 report 不混入 `dna-0`；用户采纳后，只有转译后的规则通过局部 DNA 融合进入 `dna-0`。

## 老号接手

### Step 1 - 获取老号样本

1. 自己账号：用 `wx-channel-engagement list` 拿作品管理页最近 20 条的视频描述与行内指标（播放/点赞/评论/分享/收藏）作为数据线索。
2. 完整口播文案仍需转写：用户提供视频文件或逐字稿；拿不到全部时，请用户至少提供最近 5-10 条的代表性文案。
3. 非自己账号：无后台权限，样本全部由用户提供（文字稿、视频文件、截图数据、账号简介、发布时间）。
4. 剔除重复、已删除和无完整文案的样本；保留账号简介、发布时间、内容形式、素材来源与授权信息，缺失写「未观测」。

### Step 2A：账号基本可用，用户让 Agent 接手

用户对账号目前的情况基本满意，目的是让 Agent 接手，延续目前账号的风格。

1. 将老号样本生成属于 `dna-0` 的 DNA report。
2. 若 `dna-0` 不存在：运行 `wx-channel-style-profiler build --dna-id dna-0`，建立默认 DNA 文档与 template。
3. 若 `dna-0` 已存在：新增 report 后按 `style-dna.md` 更新 `dna-0`，不覆盖重建。
4. 将 DNA 摘要、可复用规则和待校准点发给用户确认。
5. 用户意见按“用户输入转译”更新 `dna-0`，后续内容生产默认使用 `dna-0`。

### Step 2B：用户认为账号不太可用，需要推倒重来

1. 基于 Step 1 拿到的样本提炼定位、账号简介、选题组合、简介包装、内容形式、发布节奏、核心卖点与 CTA 等基础信息，将这些信息与用户确认。
2. 结合上述信息，走「从零开始打造新号」流程。
3. 如果 `business_knowledge.md` 不全，可以先从 Step 1 的样本中提取，不足的信息与用户讨论。

### 老号诊断速查

有后台数据时先自行分析（内容支柱、垂直度、调性、选题、钩子、发布频率），再向用户补问缺失信息。按视频号「社交 + 算法」双引擎视角，从失败环节倒推：

| 现象 | 可能原因 | 修法 |
| --- | --- | --- |
| 曝光低 | 账号标签弱、垂直度不足、社交启动不够、违规风险 | 收窄主题，发动真实私域看转赞，连续发布同一内容支柱 |
| 完播低 | 钩子虚、节奏慢、信息密度不均 | 前 3 秒改冲突，中段改步骤，删空话 |
| 转评赞少 | 缺少可回应点，内容没有共鸣或争议点 | 结尾问具体问题，承接真实评论 |
| 分享率低 | 内容缺社交价值（不好用 / 不值得转） | 加实用/情绪/人设价值点，配转发引导 |
| 私信少 | 缺少留资钩子或行动指令不清 | 加评论区置顶引导与私信话术 |
| 关注少 | 账号承诺不清，单条有用但系列价值弱 | 强化主页、置顶、合集和结尾关注理由 |
| 成交少 | 承接路径断、信任状弱、促单模糊 | 强化信任状与限时促单，理顺挂车/直播路径 |
| 记不住人 | 身份信号弱、人设张力弱 | 加入真实场景、短板、判断标准或系列任务 |

诊断结论按账号审计字段落盘 `wx_channel/calibration/`：当前定位、主页信号、内容垂直度、观看理由、视频描述/封面、钩子、人设张力、评论质量、承接路径、合集、合规风险、优先修复动作。
