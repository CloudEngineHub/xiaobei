# 日志审计与问题报告

## 范围与取数

先确定实例、运行版本、时间窗及时区。一次性“今天”按用户时区的自然日；周期巡检按本任务窗口或上次成功检查的时间覆盖，避免重复累计，不预置本机的两小时班次。日志 JSON 的 time 常为 UTC，不能用字符串日期前缀代替时区换算。

原生 `openclaw logs --limit 200 --plain` 适合有界查看；全窗口统计用 wrapper，读取实际 `logging.file` 及 `.1`–`.5`。Gateway 不可达时用 `--file` 指定已确认的主日志路径。默认位置是 `<stateDir>/logs/gateway.log`，不是旧参考仓日志或 `/tmp/openclaw` 的渠道日志。默认 warn、10 MiB 轮转、五份备份；实际以配置为准。

```bash
openclaw-maintenance logs --since 2026-10-29T00:00:00+08:00 --until 2026-10-30T00:00:00+08:00
```

脚本不修改日志、不自动过滤“噪音”，输出实际文件、有效记录范围、解析失败、级别计数及有限样本。原始输出可能含消息内容，留在受限工作区；对外报告前脱敏。没有记录、停写、解析失败或轮转不足均不能报告“无故障”；warn 级别下没有成功 INFO 流水也不能报告“没运行”。不把 workspace 私有巡检脚本的旧缺陷当成当前事实。

## 判定边界

| 现象 | 先核对什么 |
|---|---|
| record-missing、本地插件来源警告 | 来源与实际加载状态；不要为消提示改 plugins.allow 或伪造安装记录 |
| blocked URL fetch / 私有地址拒绝 | 具体目标、DNS/代理与业务影响；不直接放宽全局 SSRF |
| slow SQLite / lifecycle / memory pressure / prompt-cache | 延迟、趋势、复现与业务影响；一次阈值提示不证明泄漏，也不应整类静默过滤 |
| 网络断开、TLS reset、WS 超时 | 是否恢复、重试结果和影响窗口；一次重连不能推断持续故障 |
| 429 quota / throttling | 配额、限流与 fallback 结果；供应商问题仍应报告影响，归属与优先级分别标记 |
| skipped + completionStatus=failed | 读 error 的跳过原因，见 Automations 手册；长期跳过可能导致业务漏执行 |
| delivered=true | 只证明投递状态；检查最终报告正文或业务回执 |
| 插件 drain/forced retirement 超时 | 当前代次、未完成工作与实际新代码是否生效，不凭一行断定插件不支持热重载 |

不把 run 来源渠道当投递目标；`isError=true` 不证明报错已发给用户。缺成功 dispatch 日志也不证明未投递。raw_params 若已脱敏，只能引用实际可见字段，不反推成“已看到命令原文”。归属优先从任务/run/session 原生接口核对，不默认扫描所有 crew 私密会话库。

## 交付

每项写现象、次数及口径、带时间的脱敏日志/回执、影响、根因证据或待确认假设、建议与归属（本仓/上游/供应商/实例脚本）。实际故障按影响分级；观察项、已恢复/已修复项与待处理项分开。上游或供应商问题不因“本仓不能修”就从问题清单消失，处理建议可为升级、配置、供应商支持或观察。

报告保存到本 workspace `drafts/issue-report-<日期>.md`，回报路径；明确覆盖与未覆盖范围。日志审计不包含自动修复、升级、重启或真实消息测试。
